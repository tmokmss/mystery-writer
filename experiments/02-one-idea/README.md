# 02 一つの着想で書く短編「凪」

[人間に評価されるミステリーの条件](../../research/人間に評価されるミステリーの条件/report.md) の設計指針に沿って短編を書き、AIの解答役と評価役で確かめながら4稿まで直した実験。

## 結論

- **核の着想:** 「毎晩欠かさず父の夜食を作ってきた娘が、その夜だけ作らなかった。殺すつもりの相手の夕飯は作れないから」。評価役は両方とも、全稿でこの核を一文で言えた。
- **覚える情報の量:** 時刻と間取りの照合を使わずに書けた。読者が推理のために覚える情報は5〜8個に収まった。実験01の最終稿は、時刻十数個・部屋番号4つ・照明の規則複数を覚えさせていた。
- **解答役の結果:** Haikuを含め、ほぼ全員が正しい筋道で解いた。手がかりを公正に見せると、モデル間の差は出ない。これは実験01と同じ結果になった。
- **改稿で効いたこと:** 改稿の主眼は意外さで、手がかりは消さずに、物語の中で目立たなくした。
  - 作らなかった理由を語り手の口から言わせ、姉はうなずくだけにした。
  - 夜食の昔話を、父の不器用な謝り方の話の途中に沈めた。
  - その結果、正しい筋道に届く読者の予想は、Sonnetの評価役で45〜55%から20〜30%に下がった。Opusの評価役でも45%から35〜45%に下がった。
- **残った弱点:** 両方の評価役が最後まで指摘したのは、「今回は自分の店を売られた衝撃で作れなかった」という言い逃れの余地。2人とも、昔話に「母の通夜の晩も夜食は置いていた」と一文足す案を出している。実験01の轍を踏まないよう、条件を足し続けずv4で止めた。

## 方法

- 解答役と評価役の基本のプロンプトは [01のprompts.md](../01-model-gap/prompts.md) と同じ。
- 評価役には次の前提を加えた。
  - 公正さの基準は「探偵が使う手がかりを全部見せる」「犯人を早く出す」の2点とし、別解をすべて消すことは求めない。
  - 「核の着想を一文で言えるか」「読者が覚える情報の個数」「物語としての力」を採点させた。
  - 改善案は「条件を足す案より、物語の中で手がかりの効きを良くする案」を優先させた。
- 結果は [results.md](results.md)。

## ファイル

- `drafts/v1`〜`v4`: 各稿の問題編・解決編と、解答役・評価役の回答全文（`answers/`）。Codexの回答は最終回答だけを抜き出した。
