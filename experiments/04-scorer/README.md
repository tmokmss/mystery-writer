# 04 調査結果から作る採点器と、人間の判定による較正

[人間に評価されるミステリーの条件](../../research/人間に評価されるミステリーの条件/report.md) の設計指針から小説の採点器を作り、自動改善に使えるかを確かめる実験。実験01で、AIの評価役の点を上げる改稿が人間の読み味を下げた（論理パズル化した）ので、採点を自動改善の目標にする前に、人間の判定と合うかを確かめる。

## 結論（途中）

- **機械的な数え上げ:** 人間に不評だった実験01の最終稿の特徴を捉えた。問題編に出る異なる時刻は20種類で、「凪」は4、「兄の時計」は8だった。
- **馴染みのない語の抽出:** 人間が引っかかった「凪」の「蠅帳」を拾った。「布巾を使う音」は拾えなかった。
- **抽出の数字はばらつく:** 同じ稿でも、人名の数が3と1、推理に必要な事実の数が9と20に揺れた。1回の値では判断できない。
- **比較の総合:** 「兄の時計」最終稿 >「凪」最終稿 > 実験01最終稿の順だった。各作品の第1稿と最終稿では、どの作品も最終稿が勝った。読みやすさでは、どの作品も第1稿が勝った。
- **意外さは、2つの測り方で食い違った:**
  - 比較では、実験01の最終稿が意外さで2作に勝った。
  - 少しずつ読ませると、読者役（Haiku、推理なし）は二章で犯人の久我を挙げ、最後まで当て続けた。
  - 「凪」では、読者役は最後まで姉を疑わなかった。一方、人間の感想は「意外性はない」だった。
  - どちらが人間に近いかは、人間の判定が集まるまで決められない。
- **自動改善はまだ回していない:** 人間の判定と合う指標だけを使う方針で、較正の結果を待っている。

## 採点器

`scripts/score/` にある。モデルは `claude -p`（ツールなし、個人設定なし）で呼ぶ。

- `node scripts/score/score.mjs <出力ディレクトリ> <稿のディレクトリ>...`: 1稿ずつ採点する。
  - 機械的な指標: 問題編の文字数、時刻の言及数と種類、数字の数、会話の割合、解決編の文字数。
  - Sonnetによる抽出: 犯人の呼び名、人名、推理に必要な事実、馴染みのない語、核の一文。
  - 少しずつ読ませる意外さ: 問題編を章ごと（見出しが少なければ段落で4分割）に渡し、Haikuに「読み返さず、推理せず、今の印象で」犯人を3回ずつ答えさせる。章ごとに犯人を当てた割合を記録する。
  - 注意深く解く役: Sonnetに問題編を解かせ、公正に解けるかを確かめる。
- `node scripts/score/compare.mjs <出力ディレクトリ> <稿A> <稿B>`: Opusに2稿を5つの観点（意外さ・読みやすさ・読み返したときの納得・着想の面白さ・総合）で比べさせる。左右を入れ替えて2回聞き、判定が割れたら `split` とする。

## 較正

同じ6組をサイトの「どっちが面白い？」のページ（`calibrate.html`）に並べ、人間に「読んで面白かったのは」「真相が意外だったのは」を選んでもらう。組の定義は `calibration.json`。回答が集まったら、比較の判定と少しずつ読ませた結果のどちらが人間と合うかを確かめ、合う指標だけを自動改善に使う。
