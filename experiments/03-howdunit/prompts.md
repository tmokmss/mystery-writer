# プロンプト

## 解答役

サブエージェント（Haiku・Sonnet・Opus）とCodex CLI（`scripts/run_codex.sh`）に問題編だけを渡した。

```
推理クイズを解いてください。Readツールで <問題編のパス> だけを読み、ほかのファイルやWebは一切見ないでください。本文だけから考え、最後に次の形式で答えてください。
犯人: <名前>
決め手: <2〜5文。どうやったかも含める>
確信度: <0〜100>
```

## 評価役

```
推理小説の編集者として、短編ミステリーを厳しめに評価してください。Readツールで次の2ファイルだけを読み、ほかは見ないでください。
- 問題編: <問題編のパス>
- 解決編: <解決編のパス>

前提: 公正さの基準は「探偵が使う手がかりがすべて問題編で読者に見せられているか」「犯人が早く登場しているか」の二点とする。あらゆる別解を作中で消すことは求めない。抜け穴は、この基準に照らして直すべきものとそうでないものを分けること。読者は一般の日本人で、ミステリーを時々読む程度とする。

評価項目:
1. 抜け穴: 解決編の推理が成り立たない読み方、トリックの物理的・技術的な無理、犯人が言い逃れできる余地。直すべきもの／直さなくてよいもの に分ける
2. 公正さ (1-5)
3. 意外さ (1-5): 一般のミステリー読者が問題編だけで正しい筋道に届く割合の予想（%）も添える
4. 読み返したときの納得度 (1-5)
5. トリックの面白さ (1-5): 「どうやったか」が明かされたときに絵として浮かび、人に話したくなるか
6. 核の着想: 一読後、この作品の核を一文で言えるか。言えるなら一文で書く
7. 読者が覚えておく必要のある固有の情報（時刻・場所・規則・数値・人物の事実）を列挙し、個数を数える
8. 読みやすさ: 一般の読者に馴染みのない語、何を指すか分かりにくい描写、覚えにくい人名を具体的に挙げる
9. 物語としての力 (1-5)
10. 改善案: 具体的な修正を3つまで。条件を足して別解を消す案より、物語の中で手がかりの効きを良くする案を優先する
```
